Section 01

Project Overview & One-Liner

⚡ Elevator Pitch Bite Bot is an AI-powered cooking assistant that takes a YouTube or Instagram Reel URL, extracts the audio/captions, transcribes it using Whisper AI, and uses LLaMA 3.3 to generate a structured recipe with detailed nutritional data — all presented in a premium, voice-controlled, cinematic UI with RAG-based recipe suggestions and JWT authentication.

What Makes This Project Stand Out

🧠 AI/ML Features

  • Speech-to-Text — Whisper AI (with fallback model)
  • LLM Structured Output — JSON mode with LLaMA 3.3
  • RAG Pipeline — Vector search + embeddings for personalized suggestions
  • Text Embeddings — OpenAI text-embedding-3-small via OpenRouter
  • MongoDB Atlas Vector Search — For semantic similarity

🎨 Engineering Features

  • JWT Auth — Signup/Login with bcrypt password hashing
  • Rate Limiting — 3-tier (global, recipe, auth)
  • Multi-Strategy Extraction — Supadata API → yt-dlp fallback
  • Voice Control — Web Speech API (recognition + synthesis)
  • Cinematic UI — Glassmorphism + Framer Motion animations

Core User Flow

1
User signs up / logs in → JWT token stored in localStorage
2
Pastes a YouTube/Instagram URL → clicks "ENGAGE"
3
Backend extracts transcript → via Supadata API (YouTube captions) or yt-dlp + Whisper (audio)
4
LLaMA 3.3 generates structured recipe → JSON with ingredients (nutrition) + steps
5
Cinematic "Supernova" transition → Dashboard revealed with 3-column layout
6
User navigates steps via buttons or voice → Can ask AI questions, save recipes
7
RAG-powered suggestions → "What are you craving?" uses saved recipe embeddings

Design Pattern The backend follows MVC + Service Layer: Routes handle URL mapping → Middleware authenticates → Controllers orchestrate → Services do heavy lifting → Models interact with DB. This separation makes the code testable and maintainable.

models/Database schema definitions (Mongoose)Forms/templates for data
config/DB connection setupIT infrastructure

Backend Deep Dive — Every File Explained

5.1 server.js — The Entry Point

This is the first file that runs when you start the backend. It orchestrates everything:

1
Cookie Decoding — If YT_COOKIES_B64 env var exists, it decodes the base64 YouTube cookies and writes them to cookies.txt (needed for YouTube auth on cloud servers like Render)
2
Middleware Setup — CORS (whitelist localhost:5173 + Vercel domain), JSON body parsing, trust proxy (for Render)
3
Rate Limiters — 3 tiers: Global (100/15min), Recipe (10/hour), Auth (20/15min)
4
Route Mounting — /api/recipe → recipeRoutes, /api/auth → authRoutes
5
DB Connection — connectDB() calls Mongoose connect
6
Listen — Starts on PORT from .env (default 8000)
// Key middleware pipeline:
HTTP Request
  → cors()           // Cross-origin allowed
  → express.json()   // Parse JSON body
  → globalLimiter    // 100 req/15min
  → route-specific limiter (recipeLimiter or authLimiter)
  → authMiddleware   // JWT verify (on protected routes)
  → Controller       // Business logic
  → Response

5.4 recipeController.js — Core Business Logic

generateRecipe(req, res)

1. Extract `url` from req.body
2. Call getTranscriptSmart(url)  → text transcript
3. Call convertTranscript(text)  → structured JSON recipe
4. Return { message, recipe }

saveRecipe(req, res)

1. Check for duplicate (userId + url)
2. Build embeddingText from recipe title + ingredient names
3. Call OpenRouter → text-embedding-3-small → get 1536-dim vector
4. Create Recipe document with embedding
5. Return saved recipe
💡 Why Embeddings? Embeddings convert recipe text into a numerical vector. Similar recipes have similar vectors. This enables semantic search — when a user types "something spicy with chicken", the system finds recipes with similar ingredients/style using vector distance, not keyword matching.

ingredientQuery(req, res)

1. Takes question + current ingredients array
2. Builds a cooking assistant prompt
3. Sends to LLaMA 3.3 (temp: 0.5, max_tokens: 200)
4. Returns { answer }

ragQuery(req, res) — The RAG Pipeline

1. Embed user's query via OpenRouter
2. Run MongoDB Atlas $vectorSearch (top 20 candidates, recipe_vector_index)
3. Filter results to current user only
4. MODE "suggest": return top 3 matching recipes
5. MODE "generate": use top 3 as context for LLaMA → generate NEW personalized recipe

5.5 aiService.js — The AI Pipeline (Heart of the App)

downloadAudio(url, outputPath)

  • Uses youtube-dl-exec (yt-dlp wrapper) to download audio
  • Platform detection: Instagram vs YouTube (different headers)
  • YouTube: Uses extractorArgs: 'youtube:player_client=mediaconnect,web' to avoid bot detection
  • Instagram: Adds x-ig-app-id header
  • If cookies.txt exists, uses YouTube authentication cookies
  • Adds sleep intervals to look less bot-like
  • Converts to MP3 via FFmpeg

transcribeAudio(filePath)

Primary:  whisper-large-v3-turbo  (fast, high limit)
     ↓ (if 429 rate limit)
Fallback: whisper-large-v3        (solid, stricter limits)
     ↓ (if both fail)
Error:    "Bite Bot is currently saturated. Please wait 60 seconds."

getTranscriptSmart(url) — The Orchestrator

convertTranscript(transcript)

Sends transcript to LLaMA 3.3 with a detailed prompt asking for:

  • Ingredients: name, quantity, emoji, fat, protein, carbs, vitamins, purpose, alternatives, skippable, impact
  • Title: Short recipe name + creator (e.g., "Butter Chicken by Chef Ranveer")
  • Steps: Ordered cooking instructions
Config: {
  model: "llama-3.3-70b-versatile",
  response_format: { type: "json_object" },  // ← Forces valid JSON output!
  temperature: 0.3,                           // ← Low randomness = consistent output
  max_tokens: 2000
}

5.6 youtubeService.js — Caption Proxy

  • extractVideoId(url) — Regex to extract 11-char video ID from any YouTube URL format
  • getTranscript(url) — Calls Supadata API with the video ID to fetch captions
  • Handles multiple response formats (array of segments, plain text, etc.)
  • Returns cleaned, concatenated transcript text

5.7 authMiddleware.js

1. Extract token from Authorization header ("Bearer <token>")
2. jwt.verify(token, JWT_SECRET)
3. Set req.user = decoded  // { id: userId }
4. next() → proceed to controller

5.8 Utility: Cosine Similarity (Legacy)

// Used before MongoDB Atlas Vector Search was implemented
function cosineSimilarity(a, b) {
  dot = Σ(a[i] * b[i])
  return dot / (||a|| * ||b||)
  // Range: -1 to 1 (1 = identical, 0 = unrelated)
}
📝 Note This was replaced by MongoDB Atlas $vectorSearch which does the same computation but at the database level — much faster for large datasets.

MongoDB Atlas Vector Search Index

Index Name: recipe_vector_index

A special index created in MongoDB Atlas that enables $vectorSearch aggregation. It indexes the embedding field (1536-dimensional vectors) and allows approximate nearest neighbor (ANN) search for semantic similarity.

// How it's used in ragQuery():
await Recipe.aggregate([
  {
    $vectorSearch: {
      index: "recipe_vector_index",
      path: "embedding",           // Which field contains vectors
      queryVector: queryEmbedding, // User's query vector
      numCandidates: 50,          // Search breadth
      limit: 20,                  // Max results
    }
  },
  {
    $project: {
      title: 1, recipe: 1, userId: 1,
      score: { $meta: "vectorSearchScore" }  // Similarity score
    }
  }
]);
Section 08

Authentication System (JWT)

🔒 Security Details
  • bcrypt rounds: 10 — Each password hash takes ~100ms to compute (brute-force resistant)
  • JWT expiry: 7 days — After expiry, user must re-login
  • Token storage: localStorage — Sent as Bearer <token> in Authorization header
  • No refresh tokens — Simple implementation; token expires and user re-authenticates
Section 09

RAG (Retrieval-Augmented Generation) Pipeline

💡 What is RAG? RAG combines information retrieval (searching your data) with AI generation (creating new content). Instead of the AI hallucinating recipes from scratch, it first retrieves your saved recipes that are most relevant to your query, then uses those as context to generate a personalized new recipe.

Two Modes

MODE: SUGGEST

User types: "something with paneer"

→ Embed query → $vectorSearch → Return top 3 matching saved recipes

Output: Recipe cards the user can click to view

MODE: GENERATE

User types: "high protein chicken"

→ Embed query → $vectorSearch → Use top 3 as context → LLaMA generates new recipe

Output: Brand new recipe inspired by user's flavor profile

RAG Flow (Step by Step)

1
Embed the query — Send user's text to OpenRouter text-embedding-3-small → get 1536-dim vector
2
Vector Search — MongoDB Atlas $vectorSearch against recipe_vector_index: searches across ALL users (50 candidates), returns top 20 with similarity scores
3
Filter to current user — candidates.filter(r => r.userId === req.user.id) then take top 3
4a
If "suggest" → Return the 3 matched recipes directly to frontend
4b
If "generate" → Build context from top 3 recipes (title, ingredients, style) → Send to LLaMA with prompt: "Generate a recipe for [query] inspired by user's past recipes"

Why Vector Search Instead of Keyword Search?

FeatureKeyword SearchVector Search
Query: "something spicy"Only finds recipes with word "spicy"Finds recipes with chili, cayenne, jalapeño, etc.
Query: "healthy dinner"Matches "healthy" literalUnderstands low-fat, high-protein, grilled = "healthy"
Semantic understanding❌ None✅ Full
Speed at scaleFast (index on text)Fast (ANN index on vectors)

Section 16

Interview Questions & Answers

Project Overview Questions

Can you explain your project in 2-3 sentences?
Bite Bot is an AI-powered cooking assistant. You paste a YouTube or Instagram cooking video URL, the backend extracts the transcript using either the Supadata caption API or yt-dlp + Whisper AI, then LLaMA 3.3 converts it into a structured recipe with nutritional data. The frontend presents it in a cinematic, voice-controlled dashboard with AI chat and RAG-based personalized recipe suggestions.
What's the most technically challenging part of this project?
The multi-strategy transcript extraction. YouTube aggressively blocks bot downloads from cloud servers, so I implemented a smart fallback: first try Supadata API for captions (no download needed), and if that fails (no captions available), fall back to yt-dlp audio download + Whisper transcription. For Whisper, I also have a fallback from the turbo model to the standard model if rate-limited. This cascading fallback ensures reliability despite external service limitations.
How does the RAG pipeline work?
When a user saves a recipe, I generate a text embedding (1536-dimensional vector) from the recipe title and ingredients using OpenAI's text-embedding-3-small model via OpenRouter. This vector is stored in MongoDB alongside the recipe. When the user types "something spicy with chicken" in the craving search, I embed that query into the same vector space, then use MongoDB Atlas $vectorSearch to find the top 3 semantically similar recipes from that user's history. In "suggest" mode, I return those recipes. In "generate" mode, I feed those recipes as context to LLaMA 3.3, which generates a brand-new personalized recipe inspired by the user's flavor profile.

Architecture & Design Questions

Why did you choose this tech stack?
Node.js + Express for the backend because it uses the same language as the frontend (JavaScript), making context-switching minimal. Groq for AI inference because it provides extremely fast inference on open-source models with a generous free tier. React + Vite for the frontend because Vite's HMR is nearly instant. Tailwind CSS v4 for rapid styling. MongoDB Atlas because it offers free-tier vector search, which I needed for the RAG pipeline — this eliminated the need for a separate vector database like Pinecone.
Why MVC + Service Layer pattern?
Separation of concerns. Routes only handle URL mapping, controllers handle request/response logic, and services contain the reusable business logic (AI calls, downloads, etc.). This means if I want to swap Groq for OpenAI, I only change the service file. Controllers don't care about implementation details. It also makes the code testable — I can unit test services independently.
How do you handle authentication?
JWT-based stateless authentication. On signup, the password is hashed with bcrypt (10 rounds). On login, bcrypt.compare verifies the password, and a JWT is signed with a secret key (7-day expiry). The frontend stores this token in localStorage and sends it as a Bearer token in the Authorization header. The authMiddleware on the backend verifies the JWT on every protected route and extracts the user ID from the payload.
Why not use React Router for navigation?
The app only has two main views (Auth and Dashboard), and the Dashboard itself has two sub-views (Home and Recipe). Simple conditional rendering based on state (isLoggedIn, recipe !== null, activeTab) is sufficient. Adding React Router would be overengineering for this use case. If the app grew to 5+ pages, I'd definitely add it.

Security Questions

How do you prevent API abuse?
Three-tier rate limiting: a global limiter (100 requests per 15 minutes), a strict recipe limiter (10 per hour to protect Groq/Supadata free quotas), and an auth limiter (20 per 15 minutes to prevent brute-force login). I also use trust proxy so that Render's reverse proxy doesn't make all requests appear from the same IP.
Are there any security concerns with your current approach?
Yes, a few improvements I'd make: (1) Using HttpOnly cookies for JWT instead of localStorage would prevent XSS token theft. (2) Adding refresh tokens so the user doesn't need to re-login every 7 days. (3) Adding input validation/sanitization on the URL field to prevent injection. (4) CORS could be tightened to specific origins only.

Frontend Questions

How does voice control work?
I use the Web Speech API, which is built into modern browsers (best in Chrome). SpeechRecognition runs in continuous mode and listens for keywords: "next" advances the step, "back" goes to the previous step, "repeat" re-reads the current step. Any other phrase is treated as a question and sent to the AI chat endpoint. For text-to-speech, SpeechSynthesisUtterance reads each step aloud at 1.1x speed. Both are free, browser-native APIs with no external dependency.
Explain the Supernova animation.
When the user clicks ENGAGE and the recipe is ready, I set isExploding = true which renders a full-screen black overlay. Inside it, a food image (from Unsplash) animates: scale goes from 1 → 1.2 → 5, blur goes from 0 → 10px → 80px, and opacity goes 0 → 1 → 0 — all over 2 seconds. The "Bite Bot" text simultaneously scales and fades. After 2 seconds, the recipe state is set and the overlay is removed, revealing the dashboard with a staggered spring animation on each column.

Database & Scaling Questions

How does MongoDB Atlas Vector Search work?
Atlas Vector Search creates a specialized index (I named mine "recipe_vector_index") on the embedding field. It uses an Approximate Nearest Neighbor (ANN) algorithm to find similar vectors efficiently. In my aggregation pipeline, $vectorSearch takes the query vector, searches 50 candidates, returns the top 20 with a vectorSearchScore metadata. I then filter those to the current user and take the top 3. This is much faster than computing cosine similarity in JavaScript for large datasets.
How would you scale this app?
Several improvements: (1) Add Redis for caching frequently requested recipes and rate limit storage. (2) Queue long-running tasks (audio download + transcription) with a job queue like BullMQ. (3) Add WebSocket for real-time progress updates instead of blocking the HTTP request. (4) Split the monolithic Dashboard.jsx into smaller components. (5) Add a CDN for frontend assets. (6) Move to a paid MongoDB Atlas tier with auto-scaling.

Code Quality Questions

What would you improve if you had more time?
(1) Break up Dashboard.jsx (1066 lines) into smaller components — Sidebar, StepViewer, ChatPanel, etc. (2) Add error boundaries and loading skeletons instead of simple spinners. (3) Add TypeScript for type safety. (4) Write unit tests for the service layer. (5) Add input validation using Joi or Zod. (6) Implement proper error handling middleware. (7) Add WebSocket for real-time transcription progress. (8) Add recipe sharing and social features.
